# 投标模拟审核功能拆分

> 目标：新增一个独立的“投标模拟审核”模块。用户上传一个招标包和一个投标包，每个包可包含多个文件；后端先解析招标文件中的资格要求和评分标准，再用投标文件进行模拟响应审查，同时对投标文件做逻辑问题和错别字识别。

## 1. 功能范围

### 1.1 本期要做

- 创建一次投标模拟审核任务。
- 上传一个招标包，包内支持多个招标文件。
- 上传一个投标包，包内支持多个投标文件。
- 自动执行招标文件和投标文件的文件解析 / 切块 / 向量化。
- 招标文件侧抽取：
  - 资格要求。
  - 评分标准。
- 投标文件侧模拟审查：
  - 逐项响应资格要求。
  - 逐项响应评分标准。
  - 评分项结果按一键审查现有结构返回 `suggestedScore` / `fullScore`。
- 投标文件侧问题识别：
  - 逻辑问题。
  - 错别字识别。
- 返回模拟审核详情，用于前端结果页展示。
- 支持历史记录列表。
- 支持任务进度查询，优先复用现有 `biz_job` 轮询 / SSE 能力。

### 1.2 本期不做

- 不做多个投标包之间的横向对比。
- 不做项目维度的一键审查。
- 不做法律风险识别。
- 不做法律库。
- 不做导出 Excel。
- 不做人工复核工作流。
- 不做错别字自动替换，只给出识别结果和修改建议。
- 不做 OCR；扫描版 PDF 若无法抽取文本，沿用现有失败逻辑。

## 2. 推荐业务流程

1. 用户进入“投标模拟审核”页面。
2. 用户填写可选任务名称，上传招标文件和投标文件。
3. 后端创建一条投标模拟审核记录。
4. 后端为本次任务创建内部招标包和内部投标包。
5. 后端为两个包下的文件创建 `INDEX` 子任务。
6. 文件全部索引成功后，发起 `BID_SIMULATION_AUDIT` 模拟审核任务。
7. 模拟审核任务执行：
   - 从招标文件抽取资格要求和评分标准。
   - 使用投标文件对资格要求逐项响应。
   - 使用投标文件对评分标准逐项打分。
   - 读取投标文件全部 chunk。
   - 对投标文件按批次扫描逻辑问题和错别字。
   - 保存结构化结果和汇总指标。
8. 前端通过 job 轮询或 SSE 展示进度。
9. 任务成功后进入模拟审核详情页。

## 3. 已确认产品规则

- 一个模拟审核任务只包含一个招标包和一个投标包。
- 一个招标包可以包含多个招标文件。
- 一个投标包可以包含多个投标文件。
- 任务名称为可选；不填时默认取第一个投标文件的文件名。
- 资格要求和评分标准沿用 AI 审核流程。
- 资格要求和评分标准需要继续使用数据库里的检索词。
- 评分项结果要像一键审查一样逐项返回 `suggestedScore` / `fullScore`。
- 逻辑问题和错别字识别只针对投标文件。
- 逻辑问题和错别字识别沿用招标解析功能的全文 chunk 分批扫描方案。
- 暂时不做导出 Excel。
- 如果后续涉及 prompt，需要先告知并确认 prompt 设计后再实现。
- 每完成一项开发，需要同步更新本拆分文档。
- 新增或变更接口时，需要同步更新 `docs/API-投标模拟审核.md` 和 `docs/API.md` 总索引。

## 4. 与现有功能的关系

### 4.1 和招标解析的关系

投标模拟审核会复用招标解析的部分能力：

- 招标文件上传后创建内部招标包。
- 文件索引成功后读取 chunk。
- 资格要求和评分标准抽取。
- 投标文件逻辑问题和错别字识别可以复用 `TenderIssueScanPipeline` 的批次扫描思路。

区别：

- 招标解析只处理招标文件。
- 投标模拟审核同时处理招标文件和投标文件。
- 逻辑问题和错别字识别在投标模拟审核里只扫描投标文件。

### 4.2 和一键审查的关系

投标模拟审核会复用一键审查的核心审查能力：

- 使用数据库检索词召回资格要求和评分标准相关内容。
- 使用投标文件对资格要求进行响应判断。
- 使用投标文件对评分项进行建议得分计算。
- 评分项返回 `suggestedScore` / `fullScore`。
- evidence 支持前端查看原文片段。

区别：

- 一键审查基于项目和项目下的投标包。
- 投标模拟审核不依赖项目，只处理本次上传的一个招标包和一个投标包。
- 一键审查可以审多个投标包；投标模拟审核本期只审一个投标包。

## 5. 复用现有能力

### 5.1 可直接复用

- `DocumentAppService` 上传校验和对象存储能力。
- `IndexJobExecutor` 文件文本抽取、切块、embedding、chunk/vector 落库能力。
- `JobPort` / `JdbcJobRepository` 异步任务表和任务状态流转。
- `JobController` 的任务查询和 SSE 能力。
- `DocumentIndexStorePort.listChunksByDocumentIds` 读取文档 chunk。
- `ChecklistBuildPipeline` 或其公共抽取能力，用于招标文件资格要求和评分标准抽取。
- `ReviewComparePipeline` 或其公共比较能力，用于投标文件响应资格要求和评分标准。
- `TenderIssueScanPipeline` 或抽出的公共扫描能力，用于投标文件逻辑问题和错别字识别。
- `LlmPort` 已有资格/评分审查、逻辑问题、错别字相关方法。

### 5.2 需要小改或抽象复用

- 一键审查当前偏项目维度，需要支持“非项目、指定招标包 + 指定投标包”的模拟审核上下文。
- 资格/评分抽取能力如果仍绑定项目清单，需要抽成可被投标模拟审核调用的公共能力。
- 资格/评分比较能力如果仍绑定 `reviewId` 或项目投标包，需要抽成可返回结果草稿的公共能力。
- 逻辑问题和错别字扫描能力需要支持指定投标文件 chunk，而不是固定扫描招标解析里的文件。
- 上传入口需要支持两组文件：
  - 招标文件及其 `fileType`。
  - 投标文件及其 `fileType`。

- 投标模拟审核主表。

## 7. 接口建议

### 7.1 创建模拟审核任务

`POST /api/bid-simulation-audits`

`Content-Type: multipart/form-data`

参数：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 否 | 任务名称；不填则默认取第一个投标文件的文件名 |
| `tenderFiles` | 是 | 一个或多个招标文件 |
| `tenderFileTypes` | 是 | 每个招标文件的业务类型；与 `tenderFiles` 按下标一一对应 |
| `bidFiles` | 是 | 一个或多个投标文件 |
| `bidFileTypes` | 是 | 每个投标文件的业务类型；与 `bidFiles` 按下标一一对应 |

```json
}
```

## 9. Pipeline 拆分

### 9.1 `BidSimulationAuditAppService`

职责：

- 创建模拟审核任务。
- 创建内部招标包。
- 创建内部投标包。
- 上传招标文件和投标文件。
- 创建 INDEX 子任务。
- 创建 `BID_SIMULATION_AUDIT` 任务。
- 查询列表 / 详情 / 删除 / 重新审核。

### 9.2 `BidSimulationAuditJobExecutor`

职责：

- 认领 `BID_SIMULATION_AUDIT` 任务。
- 等待 / 检查招标文件和投标文件全部 `indexStatus=SUCCESS`。
- 有文件失败则整体失败。
- 调用模拟审核 pipeline。
- 写入模拟审核结果。
- 回写 job 状态。

### 9.3 `BidSimulationAuditPipeline`

职责：

- 读取招标文件 chunk。
- 读取投标文件 chunk。
- 从招标文件抽取资格要求和评分标准。
- 用投标文件对资格要求和评分标准进行响应审查。
- 调用投标文件逻辑问题和错别字扫描。
- 计算汇总指标。
- 输出可落库的主表汇总和条目结果。

### 9.4 资格要求和评分项审查

建议优先复用一键审查的比较能力：

- 资格要求结果：
  - `PASS`：符合。
  - `FAIL`：不符合。
  - `MANUAL`：待人工确认。
- 评分项结果：
  - `suggestedScore`：建议得分。
  - `fullScore`：满分。
  - `reason`：得分理由。
  - `evidence`：投标文件证据。

### 9.5 逻辑问题和错别字识别

建议优先复用招标解析已实现的全文 chunk 分批扫描能力：

- 输入只使用投标文件 chunk。
- 不使用数据库检索词。
- 按 8 个 chunk 一批。
- 并发 4 个 LLM 调用。
- 合并后落为 `LOGIC_ISSUE` / `TYPO` 条目。

## 10. 权限规则

- 仅投标方 `BIDDER` 用户可创建和查看本组织的投标模拟审核记录。
- 平台管理员访问规则后续与现有项目 / 招标解析权限保持一致。
- 记录按 `org_id` 隔离，跨组织返回 `40400`。
- 删除 / 预览 / 查看 evidence 必须校验同组织归属。

## 14. 工作量评估

整体属于中等偏上的改造。

- 上传 / INDEX 复用：较容易。
- 数据库和接口骨架：中等。
- 资格/评分抽取复用：中等，取决于现有 `ChecklistBuildPipeline` 解耦程度。
- 资格/评分响应审查复用：中等偏上，主要风险是现有一键审查是否强绑定项目和 review 记录。
- 逻辑问题 / 错别字扫描：较容易，已有招标解析实现可参考。
- 前端结果页数据结构：较清晰，但需要和一键审查字段保持一致。
- 主要风险：公共 pipeline 抽象边界、token 成本、评分结果与现有一键审查展示一致性。
